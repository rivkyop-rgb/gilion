# מה לוקחים מהעיצוב ומה לא

**כלל היסוד:** `prd.md` ו-`erd.md` הם מקור האמת היחיד לדרישות ולמודל הנתונים. קבצי Stitch הם **רפרנס ויזואלי בלבד** — לוקחים מהם את השפה העיצובית, לא את התוכן.

Google Stitch ממלא מסכים בתוכן מומצא כדי שייראו אמיתיים. חלק מהתוכן הזה נראה כמו דרישה עסקית אבל הוא סתם רעש של המחולל. המסמך הזה מפריד בין השניים.

---

## א. אלמנטים שהמציא Stitch — להתעלם מהם

אלה **לא דרישות**. הם לא מופיעים ב-`prd.md` ולא ב-`erd.md`, ולא נכנסים למימוש. אין מה להכריע לגביהם — פשוט לא לממש אותם.

| האלמנט בעיצוב                 | איפה מופיע   | למה מתעלמים                                                            |
| ----------------------------- | ------------ | ---------------------------------------------------------------------- |
| רזולוציה `300dpi`             | מסך 05       | `Newspaper.print_quality` הוא string חופשי; אין ולידציית dpi ב-MVP     |
| מודל צבע `CMYK`               | מסכים 02, 05 | אין שדה צבע במודל                                                      |
| בליד `5mm`                    | מסך 05       | אין שדה bleed במודל                                                    |
| מידות בממ״ט (`130x380 mm`)    | מסך 02       | `TemplateSlot.width/height` קיימים — היחידות ייקבעו במימוש, לא מהעיצוב |
| מע״מ                          | מסך 03       | `AdOrder.total_price` הוא סכום יחיד                                    |
| "עמלת משריך"                  | מסך 03       | לא קיים בשום מקום באפיון                                               |
| ח.פ בחיפוש לקוח               | מסך 03       | `Customer` מוגדר ב-ERD בלי ח.פ                                         |
| `ID: 88492` (מספר לקוח קריא)  | מסך 04       | ה-id הוא מזהה טכני, לא מוצג למשתמש                                     |
| "מוסף" (נפרד מעיתון)          | מסכים 03, 05 | יש `Newspaper` בלבד                                                    |
| "מיקום מבוקש" ע״י הלקוח       | מסכים 02, 06 | לא קיים באפיון                                                         |
| "הערות לגרפיקה"               | מסך 05       | לא קיים ב-`Advertisement`                                              |
| סטטוס "ממתין להגהה"           | מסך 01       | לא ב-enum של FR-4                                                      |
| "פיגור 45 יום" / "חוב אקטיבי" | מסך 04       | ה-enum הוא `unpaid / partially_paid / paid / debt` בלבד                |
| סלוט "תוכן מערכתי"            | מסך 02       | `TemplateSlot` הוא סלוט פרסומי                                         |
| פרוס כפול (`עמוד 2-3`)        | מסך 02       | `IssuePage` = עמוד בודד ממוספר                                         |
| "ייצוא ל-Excel"               | מסך 04       | לא בדרישות MVP                                                         |
| `100MB` / `10MB` קשיחים       | מסכים 05, 06 | FR-21: הגודל מוגדר לכל עיתון ב-`Newspaper.max_ad_file_size`            |

> שים לב שהעיצובים אף סותרים את עצמם — 100MB במסך אחד ו-10MB באחר. עוד הוכחה שאלה מספרים אקראיים ולא דרישות.

**במימוש:** כשמסך מבוסס על עיצוב שמכיל אחד מאלה — משאירים את הפריסה ומחליפים את התוכן בשדות האמיתיים מ-`erd.md`. למשל, כרטיס "דרישות קובץ" במסך 05 נשאר כרכיב, אבל מציג רק את הפורמטים המותרים ואת `max_ad_file_size` של העיתון שנבחר.

## ב. מה כן לוקחים — השפה העיצובית

זה החלק שכן מחייב, ומתועד ב-[design-system.md](design-system.md), [app-shell.md](app-shell.md) ו-[components.md](components.md):

- **פלטת הצבעים** — נייבי/כמעט-שחור כ-primary, זהב למצב פעיל, היררכיית משטחים תכלת-לבן, חמישה צבעי סטטוס סמנטיים
- **מבנה המעטפת** — סיידבר ימני 280px, סרגל עליון, אזור תוכן עם breadcrumb וכותרת סריף
- **דפוסי הרכיבים** — badge גלולה עם אייקון, כרטיס KPI עם גבול צדדי סמנטי, טבלה צפופה עם עריכה inline, אזור גרירה, כרטיס קובץ עם מצב שגיאה
- **פתרון לוח השיבוץ** — שלושה פאנלים, קנבס עמוד עם סלוטים בארבעה מצבים, סרגל מיניאטורות עמודים
- **הפרדת פורטל הלקוח** — מעטפת נפרדת לגמרי, ללא סיידבר, עמודה ממורכזת ומרווחת
- **בורר גודל מודעה כמלבנים בפרופורציה** (מסך 06) — פתרון מוצלח, שווה לשמר
- **כללי RTL** — סיידבר ימין, `border-r-4` על פעיל, logical properties

### שתי הכרעות עיצוביות שנשארו פתוחות

אלה עיצוביות טהורות ולא נוגעות באפיון:

1. **פונטים עבריים.** Libre Caslon Text ו-Hanken Grotesk חסרי גליפים עבריים — מה שנראה בצילומים הוא fallback. המלצה: **Frank Ruhl Libre** (סריף, שומר על התחושה העיתונאית) + **Heebo** או **Assistant** (סנס).
2. **טוקן הזהב.** הלוגו משתמש ב-`#D4AF37`, הטוקן של Stitch הוא `#fed65b`. המלצה: שני טוקנים — `brand-gold` ללוגו ומבטאים, `state-active` להדגשת מצב פעיל.

## ד. חוסרים רוחביים בעיצובים הקיימים

גם אלה יושלמו בהמשך לפי אותו קו:

- **מצבי ריק** — אף מסך לא מראה איך הוא נראה לעסק חדש
- **מצבי טעינה** — skeletons
- **מצבי שגיאה** — כשל שרת, אין הרשאה, לא נמצא
- **ולידציית טפסים** — שדה שגוי, הודעת שגיאה, שדה חובה
- **מובייל וטאבלט** — כל 6 המסכים בדסקטופ בלבד
- **וריאציות לפי תפקיד** — FR-8: Designer לא רואה נתוני תשלום
- **מצבי Drag & Drop** — קריטי ללוח השיבוץ: נגרר, יעד תקף, יעד חסום
- **דיאלוגי אישור** — ביטול פרסום, סגירת גיליון
